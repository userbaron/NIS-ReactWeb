# Командный трекер

Небольшое приложение для работы с командой и её задачами. Можно посмотреть участников, открыть профиль, добавить человека в избранное, создать задачу, изменить её или удалить. Задачи можно отбирать по статусу.

Использованы React, React Router, Redux Toolkit, RTK Query и Express.

## Запуск

Нужен Node.js 22.12 или новее. Все команды выполняются из папки S06.

Сначала установить зависимости:

```bash
npm ci
```

В первом терминале запустить сервер:

```bash
npm run api
```

Во втором терминале запустить интерфейс:

```bash
npm run dev
```

Открыть адрес, который напечатает Vite. Обычно это http://localhost:5173. Сервер работает на http://localhost:3001.

Другие команды:

- `npm run build` — собрать проект.
- `npm run preview` — посмотреть сборку. Сервер API при этом тоже должен работать.

## Страницы

| Адрес | Что открывается |
| --- | --- |
| /users | Все участники |
| /users/1 | Профиль участника |
| /users/1/tasks | Его задачи |
| /users/1/tasks?status=todo | Его задачи к выполнению |
| /tasks/1 | Просмотр и изменение задачи |
| /favorites | Избранные участники |
| Неизвестный адрес или ID | Страница 404 |

## Где хранятся данные

| Данные | Место хранения |
| --- | --- |
| Участники и состояние их загрузки | usersSlice |
| ID избранных участников | uiSlice и localStorage |
| Загруженные задачи | Кэш RTK Query |
| Выбранный участник, задача и фильтр | Адрес страницы |
| Текст, который вводится в форме | useState |
| Постоянные данные сервера | server/db.json |

При первом запуске сервер создаёт базу из server/seed.json. В ней четыре участника и восемь задач. ID хранятся строками. Изменения записываются в файл, поэтому задачи сохраняются после перезагрузки страницы и перезапуска сервера.

## Как это работает

Участников загружает мой middleware через fetch. Он отправляет actions начала, успеха и ошибки, а usersSlice сохраняет результат. Проверка loading не допускает одновременных дублей, requestId защищает от старых ответов. next(action) передаёт action дальше, и middleware возвращает его результат.

Для задач я описал запросы в RTK Query. Библиотека сама хранит ответы, загрузку и ошибки. После изменения задачи теги помогают обновить нужные списки и детали. Отдельного tasksSlice нет. Кэш хранится ещё 60 секунд после ухода последнего компонента, использующего запрос.

В избранном хранятся только ID. Selectors находят по ним участников и считают их количество. Поэтому избранное совпадает на всех страницах.

React Router переключает страницы без перезагрузки. UserLayout содержит общий заголовок участника, Outlet — профиль или задачи. Фильтр хранится в URL, поэтому работают прямые ссылки и «Назад/Вперёд». Код страницы задачи загружается через lazy.

При ошибке сохранения текст остаётся в форме. Пустое название не отправляется на сервер.

## Что показать на защите

1. Прямой вход по /users/1/tasks и избранное на разных страницах.
2. Создание, изменение и удаление задачи, сохранение после перезапуска API.
3. Фильтр, «Назад/Вперёд» и повторное открытие данных из кэша.
4. Ошибка при выключенном API и успешный повтор после его запуска.
5. Проверка пустого названия и неизвестного адреса или ID.

В Redux DevTools можно посмотреть actions загрузки участников и запросов RTK Query. В Network видны сами обращения к серверу.
